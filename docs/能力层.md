# 能力层（networking / 能量 / 配置系统）

横切能力插座（第 8 类 capabilities），以 `requires: [block-entity]` 挂接到机器类套路，通过 `capabilities` 上下文**注入**现有模板——不复制模板、不改引擎。

## 三个插座

| 插座 | 编号 | 产出 |
|---|---|---|
| networking | 51 | `networking/Network.java`（SimpleChannel，hub 聚合）+ 每机器 `C2SPacket`/`S2CPacket` 独立类 + 外壳 `Network.register()` |
| energy | 52 | 纯注入：方块实体 `ForgeEnergyStorage` 字段 + `getCapability(ENERGY)` 分支 + 耗能门/`consumeEnergy()` |
| config-system | 53 | `config/ModConfig.java`（ForgeConfigSpec，int/double/boolean 三型）+ 外壳 COMMON 配置注册 |

## networking 行为语义

- **C2S**：GUI "Clear" 按钮（Screen 注入 `mouseClicked` + 按钮绘制）→ `sendToServer(C2SPacket(pos, action))` → 服务端 `BE.handlePacketAction(0)` 清空输出槽；
- **S2C**：加工完成时 `PacketDistributor.TRACKING_CHUNK` 推送 `S2CPacket(pos)` → 客户端聊天栏通知；
- **多机器共享通道**：所有 networking 实例的 `networkClassName/channelPath/protocolVersion` 必须一致（生成期一致性校验），消息 ID 由生成器按序分配（C2S/S2C 各占一号）；
- 协议版本号参数化，`withC2S/withS2C` 可裁剪。

## energy 行为语义

- `ForgeEnergyStorage(capacity, maxReceive, maxExtract)` + `onEnergyChanged → setChanged()`；
- `consumePerTick > 0` 时 tick 增加耗能门：无配方不耗能；能量不足时 `resetProgress()` 并跳过本 tick（模拟停机）；
- `consumePerTick = 0` 时只存不耗（测试断言无 `consumeEnergy` 方法）。

## config-system 行为语义

- 条目：`{key, type: int|double|boolean, default, min?, max?, comment?}`，字段名 = key 大写；
- 生成 `IntValue/DoubleValue`（`defineInRange`）与 `BooleanValue`（`define`，`default: false` 正确渲染）；
- 主类构造器注册 COMMON 配置（`<modid>-common.toml`）；
- **已知留白**：配置值尚未接线到模板参数（如 BE 的 craftTime 仍是插座参数），接入方式为在模板中用 `ModConfig.CRAFT_TIME.get()` 替换——后续按需注入。

## 注入机制（复用要点）

- 生成器构建 `capabilitiesByBe`（beClassName → {networking?, energy?}）与 `menuBeMap`；
- fileCtx 注入规则：block-entity 按自身类名、menu 按 beClassName、screen 经 menuClassName 间接查；
- 模板用 `{{#if capabilities.networking}}`/`{{#if capabilities.energy}}`/`{{#if params.energyConsumes}}` 守卫注入段；
- 无能力时模板保持原样（"干净基线"测试：plain 机器无 ForgeEnergyStorage/handlePacketAction）。
